Project 4: Load Balancer

A clock-driven simulation of requests, workers, and changing capacity.

System design

Configuration + user input
↓
Main: finite simulation loop
↓
Persistent random generator → Request
↓
Validate fields + source-IP firewall
↓ accepted   /   rejected → counters
FIFO waiting queue
↓ idle worker available
WebServer: one request + countdown
↓ countdown reaches zero
Completed counter + server available

One simulation cycle

  1. Dispatch waiting requests to idle servers.
  2. Advance active requests one cycle and count completions.
  3. Randomly generate a new batch and queue accepted requests.
  4. At the scaling interval, compare waiting work with the live server count.

Requests assigned at the start of a cycle process immediately. Arrivals at the end wait for the next cycle. At the time limit, waiting and active work remain unfinished and appear in the summary.

Scaling policy

Above 80 requests per server, allocate one additional server. Below 50 per server, remove one idle server. Keep at least one server. If every server is busy, postpone removal. Wait the configured interval between checks.

Class responsibilities

Request
Source IP, destination IP, required cycles, and P/S job type.
WebServer
Current request, busy state, and remaining cycles.
LoadBalancer
Owns the queue, workers, random engine, clock, firewall admission, scaling, and statistics.
main.cpp
Reads settings into ordinary variables, gets user input, and controls arrivals and scaling.

Evidence and reporting

Quiet mode shows starting/ending summaries. Verbose mode adds useful events. The same messages are saved to a plain-text log. Accepted work must equal completed work plus queued work plus work in progress.
